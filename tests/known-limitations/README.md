## 原问题：块内 `let` 覆盖外层同名绑定

自举后端的符号表是**函数级扁平**的：块内 `let` 会**原地覆盖**外层同名绑定，
块之后的代码于是解析到内层槽位。

    fn pick(op: string): string {
        let v = "outer";
        if op == "/" {
            let v = "inner";
            return v;
        }
        return v;          // 读到内层槽 -> 应回到 outer
    }

修复前：解释器与 C++ 后端输出 `inner` / `outer`（正确），自举后端输出
`inner` / `inner`（静默误编译，退出码 0，只是答案错）。

## 修法：符号表分层，而不是给名字加深度后缀

第一版尝试给名字加嵌套深度后缀（`name@depth`，查表由内向外找）。语义是对的，
但**它编译出的编译器只要一碰除法就 0xC0000005 崩溃**，`.ll` 都写不出来。

隔离过程（每步都重建两代再测除法）：

| 变体 | gen2 除法 | 遮蔽 |
|------|-----------|------|
| 真实深度 + `name@depth` 键 | **崩溃** | 正确 |
| `st_depth()` 恒返回 0 | 正常 | 失效 |
| 真实深度计算 + 扁平键（忽略深度） | 正常 | 失效 |

第二、三行一起把范围钉死了：`st_stack_entries` / `st_depth` 本身没问题（第三行
仍然真实计算深度却一切正常），**触发崩溃的是带 `@` 的键字符串**。

于是换成不新增结构体字段、也不引入新算术的方案：符号表仍是 `name:irtype:slot`
的扁平文本，但用一行标记 `~BLOCK` 分层。

- 进块：追加 `~BLOCK\n`（`st_push_if` / `st_push_loop`）
- 出块：截断到最后一个 `~BLOCK` 之前（`st_pop_stack`）
- 查表：取**最后一次**匹配，也就是最内层的绑定
- 声明：只在当前层内覆盖，外层同名条目留着

全部是普通字符串操作，没有深度计算，也没有特殊字符参与键匹配。两代自举后除法
与遮蔽同时正确，不动点成立。

## 顺带修掉的一处真误编译

`emit_binop` 曾有三处 `let opcode`（逻辑运算/算术/除零分支），其中除零分支遮蔽了
算术分支的绑定，导致任何含 `+` 的程序都被编译成 `%t4 =  i64 ...`（opcode 丢失）。
遮蔽修好后这类问题不再复发，但命名已改为 `logic_op` / `div_op`。
